Step indicators:

Completed: filled circle with ✓, primary blue
Current: pulsing ring animation (framer-motion animate={{ scale: [1, 1.2, 1] }}), primary blue
Pending: empty circle, border only, muted
Steps (adjust to match your contract's actual flow):

Approve (ERC-20 only — skip for native MC) — wallet approval tx
Send — call bridge contract bridge() function, wallet signs
Relay — waiting for relayer / destination chain to pick up — polled every 5 s
Done — destination tx confirmed

Responsive Behaviour
Desktop (≥ 768 px): widget centered, max-width 480 px, modals centered with backdrop
Mobile (< 768 px): full-width widget with px-4, chain/token modals as bottom sheets with drag-to-dismiss, amount input triggers numeric keyboard
Safe area insets respected for bottom sheet on iOS (padding-bottom: env(safe-area-inset-bottom))
Empty & Error States
Situation	UI
Wallet not connected	Dimmed amount input + "Connect wallet to see balance"
RPC error loading balance	"—" with retry icon, tooltip "Failed to load"
Bridge contract read fails	Warning banner above button: "Could not estimate fees — proceed with caution"
Unsupported chain selected	Error card inline: "Bridging from [chain] is not yet supported"
Transaction rejected by user	Toast: "Transaction cancelled" (bottom center, 3 s, dismissible)
Quality Bar
TypeScript strict — no any
All amounts as BigInt — no float arithmetic on-chain values
All token decimals respected in formatting (formatUnits from viem)
Transaction polling uses exponential backoff — not a fixed interval hammer
No fake/mock data — if a value isn't loaded yet, show a skeleton; if it failed, show the error
aria-label on all icon-only buttons, keyboard navigable, focus-visible rings matching primary color
